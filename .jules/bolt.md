## 2024-06-21 - Optimize String Sorting with Pre-instantiated Intl.Collator
**Learning:** `String.prototype.localeCompare` is surprisingly slow in JavaScript engines when used inside loop-heavy operations like `Array.prototype.sort()` because it re-initializes collator rules on every invocation. In our codebase, dashboards frequently sort lists of projects, episodes, and settings using `localeCompare`, which creates a noticeable bottleneck for larger datasets.
**Action:** When implementing custom string sorting logic, always prefer creating a singleton `Intl.Collator` instance outside the loop/comparator and using its `.compare` method. A set of pre-instantiated collators (e.g., `comparePtBr`, `comparePtBrVariant`, `compareEnVariant`) is now centralized in `src/lib/search-ranking.ts` to be reused across the application.
